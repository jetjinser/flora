# SMathML in Flora

The seven Racket page modules and their helper in `source/` are copied from the SMathML Everything
site's source tree at
[`alpha-beta-eta/alpha-beta-eta.github.io`](https://github.com/alpha-beta-eta/alpha-beta-eta.github.io),
commit `a848fdf599775359de665d88d1db5b6977d66718`. They are kept as source,
not converted into static HTML: Flora evaluates each exported SMathML document
while building its corresponding `.plant` tree.

`plants/smathml.plant` and the six trees under `plants/smathml/` correspond to
the original Everything index and its listed child pages. All seven pages are
generated by SMathML. Grove's
render rule runs Racket, reads the generated HTML/MathML, and places the body
inside Flora's normal page shell. The page modules are listed as build inputs,
so editing one invalidates the generated page.

The bridge records the source site's internal page links as Grove link nodes
before analysis, so Grove can validate them and build reference/backlink
backmatter. The route table is checked against each generated SMathML document
when it renders; a changed or unmapped internal link fails the build instead
of silently drifting from Grove's relation graph.

SMathML is pinned in `smathml/manifest.scm` to upstream commit
`20dfc39ddf60688870e54cfeaa6215297ea21d0c`. The toolchain is defined
separately from Flora's base manifest. Load both manifests for a full build:

```sh
guix time-machine -C channels.scm -- shell \
  -m manifest.scm -m smathml/manifest.scm -- grove build
```

The full Flora build needs this toolchain because the site includes these
Racket-generated pages. Flora's Guix `.envrc` activates both manifests.

This experiment intentionally preserves SMathML's Racket source and generation
model. It does not translate SMathML into Grove's math DSL or claim that the two
systems have the same semantic model.
